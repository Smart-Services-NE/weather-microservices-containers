# Product Guidelines: ContainerApp\n\n## Design Principles\n- **Clarity:** Ensure every feature has a clear purpose and value proposition.\n- **Consistency:** Maintain uniform naming conventions and interface patterns across all microservices.\n- **Resilience:** Design for failure; ensure the system remains functional even if some components are degraded.\n- **Observability:** Every significant action should be traceable and measurable.\n\n## User Experience (UX)\n- **Responsive Dashboard:** The frontend should provide a seamless experience on various screen sizes.\n- **Interactive Feedback:** Users should receive clear feedback for actions, especially asynchronous ones like notification triggers.\n- **Error Handling:** Present errors gracefully to users, providing helpful context without exposing system internals.\n\n## Prose and Documentation\n- **Technical Tone:** Documentation should be precise, clear, and focused on enabling other developers.\n- **Self-Documenting Code:** Prioritize clear naming and structure over extensive comments.\n- **Up-to-Date Documentation:** Ensure changes in functionality are reflected in the corresponding documentation.\n\n## Development Style\n- **Adherence to IDesign:** Strictly follow the layered architecture (Managers, Engines, Accessors).\n- **Test-Driven:** Maintain high test coverage for both unit and integration tests.\n- **Security First:** Protect credentials and sensitive information by using environment variables and secrets management.
